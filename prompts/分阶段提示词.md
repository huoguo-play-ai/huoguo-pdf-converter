# 火锅PDF转换器 · 分阶段提示词（朴素版）

用法：新建一个空文件夹，放几份要测试的 PDF（简历、表格、合同各一份最好），在 DeepSeek Harness 里把这个文件夹设为工作区。然后按顺序发下面 4 段，每段等它做完、汇报完再发下一段。每段大约 15～20 分钟，全部做完一个半小时左右。

每一步也有图片版，见 [images](images/) 文件夹。

---

## 第一步：把 PDF 一个字一个字地读出来

```
我想从零做一个 PDF 转 Word 的小工具，名字叫「火锅PDF转换器」。整个工具分 4 步做，这是第 1 步。

【先说清楚整体要求，后面每一步都要遵守】
1. 只在当前文件夹里工作。不要参考网上或电脑里现成的 PDF 转 Word 项目，也不要直接套用现成的「PDF 转 Word」转换库（比如 pdf2docx、mammoth）。
2. 但「打开和读取 PDF」这件事，必须用 Mozilla 的 pdf.js（就是 Firefox 浏览器自带的那个 PDF 阅读器）来做，不要自己从头写 PDF 解析器。PDF 的格式非常复杂，自己写的往往只能读一部分文件，换一个软件导出的 PDF 就读不出来了。
3. 最终做成一个网页文件「火锅PDF转换器.html」，我双击就能打开用，不用安装任何东西。
4. 断网也能用，PDF 文件不能上传到任何地方。
5. 转出来的 Word 要和原 PDF 长得几乎一样，而且打开后能直接改字。

【这一步要做的事】
让工具能把 PDF 里的内容「一个字一个字」地读出来，不要整段读。每个字都要记下：
- 是什么字；
- 在页面上的位置：左边、右边，以及这个字的底线在哪里（就像写字时作业本上的那条横线）；
- 字有多大、用的什么字体、什么颜色。
另外还要记下：
- 页面上所有的方块和线条：位置、大小、填充颜色、边框颜色、线有多粗；
- 页面上所有的图片：位置、大小，并把图片本身保存下来。
如果整份文件平均每页读出来不到 10 个字，说明它是扫描件（整页都是图片），工具要直接提示「这是扫描件，暂不支持」。

【做完后请自己检查】
做一个检查用的网页：把 PDF 页面显示出来，在每个字外面画红框，在方块和线条外面画蓝框，在图片外面画绿框。拿简历试一下：
- 红框应该刚好框住每个字，不偏不倚；
- 照片外面有绿框；
- 小标题左边的彩色竖条、标题下的细横线、灰底说明框外面都有蓝框；
- 扫描件能被认出来；
- 一个字都不能少：每份 PDF 读出来的字数，要和 pdf.js 自带的 getTextContent 数出来的字数一致（只是用来核对，读取本身还是一个字一个字地读）。
做完告诉我结果，然后停下等我。

【给 AI 的技术备注（看不懂可以跳过）】
- 只用三个库：pdfjs-dist 3.11.174、jszip 3.10.1、docx-preview 0.3.7，下载到本地 lib 文件夹（国内可用 registry.npmmirror.com）。
- 双击打开（file://）时浏览器不允许读取本地文件、也不允许开后台线程，所以：先用 script 标签加载 pdf.worker.min.js，再加载 pdf.min.js，不设置 workerSrc；把 cmaps 文件夹里的 .bcmap 转成 base64 写进一个 js 文件，用自定义 CMapReaderFactory 读取；不要用 ES module，不要 fetch 本地文件。
- 逐字读取要用 page.getOperatorList()，自己跟踪变换矩阵、文字矩阵、字体、字号、颜色和 save/restore，不要用 getTextContent。字号 = |字号 × 变换后矩阵的 d|，字宽 = glyph.width × fontMatrix[0] × 字号。
- 所有长度用 PDF 的「点」，坐标原点放在页面左上角。
```

## 第二步：认出版式

```
继续第 2 步：根据上一步读出来的字和图形，认出这一页的「版式」。还是只在当前文件夹里工作。

【要认出来的东西，按这个规则来】
1. 哪些字是同一行：两个字的底线高度差，不超过字高的四分之一（最少按 1.5 点算），就算同一行。
2. 一行里分左右两块：同一行里两个字之间空出来的距离，超过 2.5 个字那么宽（最少 18 点，大约 6 毫米），就从这里拆开。比如左边是公司名、右边是日期。
3. 哪些行是同一段话：同时满足下面几条，就把下一行并进上一段：
   - 上一行一直写到了右边，离右边不到 1.5 个字的距离（说明是自动折行，不是主动换行）；
   - 两行字的大小、颜色一样；
   - 两行左边对齐（如果上一段是小圆点条目，下一行要和圆点后面的正文对齐才算）；
   - 两行之间的距离在 1 到 2 个字高之间；
   - 下一行开头不是「•」「-」「*」这类小圆点或符号。
4. 粗体：字体名字里带 Bold、Medium、Heavy、Black 的，算粗体。
5. 小圆点条目：一行开头是「•」「●」「■」这类符号的，记下符号后面正文开始的位置，后面用来对齐折行。
6. 图形分类：
   - 很窄的竖长条（宽不超过 6 点，高 4 到 40 点）是小标题旁边的「彩色竖条」；
   - 很扁的长条（高不超过 2.5 点，长超过 40 点）是「横线」；
   - 比较大的、有底色或有边框的方块（宽超过 30 点、高超过 8 点）是「灰底框」；
   - 横线和竖线围成至少两个格子的，是「表格」，要算出每一列的宽度、每一行的高度，以及每个格子里有哪些字。

【做完后请自己检查】
在第 1 步的检查网页上，再加几种框：每一行一个橙框、每一段一个紫框、竖条涂绿、横线画红线、灰底框涂黄、表格画出格子。拿简历和表格 PDF 试一下：
- 「个人简介」那两行应该是同一段；
- 「公司名 …… 日期」是一行里的左右两块；
- 每个带小圆点的条目单独成段；
- 竖条、横线、灰底框都认对了；
- 表格的行数、列数和原来一样，每个格子里的字都在。
做完告诉我结果，然后停下等我。
```

## 第三步：生成 Word

```
继续第 3 步：把认出来的版式写成 Word 文件。还是只在当前文件夹里工作。

【最重要的原则】
不要用「文本框」把字一块块摆上去，那样在 Word 里没法正常编辑。要用 Word 自己的排版功能（段落、缩进、对齐、边框、表格）来还原位置。

【具体怎么做】
1. 页面：Word 页面大小和 PDF 一样。左边距 = 页面上最靠左的内容的位置；上边距 = 最上面的内容再往上留 10 点。
2. 让每一段落在原来的高度上：
   - 每一段都设成「固定行距」：只有一行的段落，行距 = 1.3 倍字号；有多行的段落，行距 = 原文里两行之间的距离。
   - 再用「段前距离」把它往下推到原来的位置：段前距离 = 这一段的顶 − 上一段的底。
   - 这一段的顶 = 第一行的底线 + 0.18 倍字号 − 行距；上一段的底 = 它最后一行的底线 + 0.18 倍字号。
   - 有多行的段落用两端对齐。
3. 左右位置：段落的左缩进 = 这一段离页面左边距的距离。
4. 一行里分左右两块的：用 Word 的「制表位」把右边那块放过去。如果右边那块在页面右半边，就用「右对齐制表位」，对准它的右边缘，这样日期会紧贴右边。
5. 小圆点条目：小圆点单独用 Arial 字体，后面跟一个制表符，整段设「悬挂缩进」到正文开始的位置，这样折行后的文字和第一行对齐。
6. 彩色竖条 → 这一段的「左边框」，颜色和粗细跟竖条一样。
7. 横线 → 插一个只有 0.7 点高的空段落，给它加「下边框」。
8. 灰底框 → 给框里的段落加灰色底纹（颜色用原来框的填充色）和四周边框。注意：框的上下留白要算进这一段自己的位置里，不能让框后面的内容整体往下挪。
9. 表格 → 做成 Word 真正的表格，列宽、行高固定成原来的大小。
10. 照片 → 做成「浮动图片」，位置相对整页来定，放在原来的地方。
11. 字体：中文统一用苹方（Mac）或微软雅黑（Windows），粗体照原样；关闭 Word 的「中英文之间自动加空格」。
12. 防止 Word 报「文件已损坏」：段落格式里的各项设置，要按 Word 规定的先后顺序写（见技术备注）。

【做完后请自己检查】
把几份测试 PDF 都转一遍，打开 Word 和原 PDF 对比：
- 能正常打开，没有「文件已损坏」的提示；
- 文字一个不少：把 Word 里的文字和 PDF 里的文字逐字比对，不能丢字、多字或者顺序错乱；
- 每一行的高度和原来一样，不会越往下越歪；
- 名字、小标题是粗体；
- 日期紧贴右边；小圆点条目折行后对齐；
- 竖条、横线、灰底框、表格、照片都在原来的位置，灰底框有灰色底色；
- 两端对齐的段落里，字和字之间没有被拉得特别开；
- 能直接点进去改字。
做完告诉我结果，然后停下等我。

【给 AI 的技术备注（看不懂可以跳过）】
- 用 jszip 直接写 word/document.xml 等文件，不要用 docx 生成库。
- 单位换算：1 点 = 20 twip（缩进、行距、制表位用）= 12700 EMU（图片用）。行距用 w:spacing w:lineRule="exact"，段后为 0。
- 字体设置要同时写 w:ascii、w:hAnsi、w:eastAsia；在每个段落里写 autoSpaceDE、autoSpaceDN 为 0。
- 照片用 wp:anchor，positionH / positionV 都相对 page。
- w:pPr 子元素顺序：pageBreakBefore、widowControl、pBdr、shd、tabs、autoSpaceDE、autoSpaceDN、spacing、ind、jc。pBdr 里依次 top、left、bottom、right。
- 对外提供一个函数：输入 PDF 文件，返回 { 是否成功, 页数, Word 文件, 状态, 错误提示 }。
```

## 第四步：做界面

```
继续第 4 步：转换功能已经确认，现在做界面。不要改动转换部分的代码，除非发现明显的 bug，并告诉我改了什么。

【整体风格】
- 浅蓝灰色背景（#F3F6FB），蓝色主色（#1F5FE0），白色大圆角卡片，柔和的阴影，干净好看。
- 图标用简单的线条图标，不要用表情符号。
- 左上角：蓝色小方块里一个白色文档图标，旁边写「火锅PDF转换器」。右上角：一个白色小标签，写「断网可用 · 文件不出电脑」。

【页面的几个状态】
1. 首页：居中的大标题「PDF 拖进来，Word 带走」（后半句用蓝色），下面一行小字「排版几乎不变，打开就能直接改」。再下面是一个大大的虚线拖放区：「把 PDF 拖到这里」「支持一次拖入多个文件」，和一个蓝色「选择文件」按钮。整个页面都可以拖文件进来，拖着文件经过时拖放区要变色提示。
2. 选好文件后：显示文件列表，每个文件一行，写文件名、页数、大小、「等待中」。下面有蓝色按钮「开始转换（N 个文件）」、字体选择（苹方 / 微软雅黑）和「清空」按钮。
3. 转换中：左边显示当前 PDF 第一页的小图，中间用大字写「正在重排」，下面是进度条和「第 x / N 个文件」。
4. 转换完成：
   - 顶部显示「N 个文件全部完成 · 用时 x 秒」（用的是真实转换时间）；扫描件被跳过不算失败。
   - 左边是一个对比窗口：原 PDF 和转好的 Word 叠在一起，中间有一条可以左右拖动的分割线，左边看 PDF、右边看 Word。
   - 右边是结果列表：每个文件可以单独下载；点一下就在左边切换对比；下面有「全部下载（zip）」和「再转一批」按钮。
   - 扫描件在列表里显示「扫描件已跳过」。

【做完后请自己检查】
双击打开「火锅PDF转换器.html」，拖进几份 PDF（包括一份扫描件），走一遍：选文件 → 转换 → 拖动对比 → 下载单个 → 下载 zip。检查：
- 断网也能正常转换；
- 页面没有被挡住或挤出屏幕的地方；
- 窗口拉窄（像手机那么宽）时布局也不乱。
做完告诉我结果。

【给 AI 的技术备注（看不懂可以跳过）】
- 对比窗口右边用 docx-preview 渲染 Word，左边用 pdf.js 渲染 PDF，两层叠放，上层用 clip-path 按分割线位置裁剪。docx-preview 渲染时把页面缩放到和 PDF 一样大，字体回退用无衬线字体。
- docx-preview 显示浮动图片的位置不准，这是预览库的问题，不要为此改 Word 的生成方式；预览渲染完后用 JS 按图片的 posOffset（EMU ÷ 12700 = 点）把图片绝对定位回原处即可。
- zip 用 jszip 打包。
```
